# Provider archive seeking (no local recording)

`GET /playback/rewind?id=ch:…` requires the existing authenticated principal and a present profile/enabled channel source. It returns `provider_archive` only for a known supported catch-up format with advertised retention. `advertised_start` and `advertised_end` describe the last 60 minutes, aligned to UTC minute boundaries. `verified` is always false: metadata is not a successful provider playback probe. `recording_enabled` is always false.

`POST /playback/resolve` accepts timezone-aware `rewind_at` only for channels and separately from `catchup_programme_id`. Seconds are rounded down to the provider's minute granularity. Requests outside the current advertised window fail with `rewind_expired`, requiring the user to select a newer position or Go Live. Existing adapters construct a finite archive request from the selected minute to the current minute; no extra provider connection is opened during resolution. Descriptors include actual requested `archive_start/end`, `live:false`, and duration. Existing stream ownership, connection budget and recovery controls still apply when a client opens the stream.

Past-programme catch-up now verifies programme feed/channel identity and retention before resolving. Disabling a source rejects capability/resolve requests. This adds no new profile-access policy; integration must continue to apply the shared parental policy at all playback entrypoints.

Web channel identity remains separate from descriptor live state: a channel archive permits finite seek controls and retains channel navigation/Go Live. Archive selection supports D-pad Left/Right minute adjustment and center Select; fine seeking uses only the actual media element's seekable ranges, avoiding invented buffer positions. Provider TS archives may not offer byte-range seeking; minute-based archive reload is the supported fallback. This is not a claim of universal continuous scrubbing or 60 minutes of playable history.

## Remaining local-buffer decision

No recorder, disk allocation or buffer activation is implemented. Channels without advertised provider archives remain unavailable for rewind. Proposed fallback requires explicit storage/activation approval: one actively watched channel only, codec-copy HLS, maximum 12 GiB total, 5 GiB free-space reserve, 60-minute rolling retention, removal on session termination and bounded orphan cleanup. At 20 Mbps an hour is approximately 9 GB before overhead; higher-rate streams must not silently exceed quota or claim a full hour. Pause requires an explicit viewer lease rather than segment requests; after an hour an old paused point expires honestly. Server restart, Stop all streams, final viewer cancellation, quota exhaustion and concurrent admission require fixture tests before enabling this separate implementation.

Current production metadata reportedly advertises 978 archive-capable channels; that count was supplied by the integration owner and is not verified playback. No live provider tests or recording were performed for this change.
